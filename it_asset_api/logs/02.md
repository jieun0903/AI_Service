## 아직 검사하지 못한 조건

- 재고 1인 장비에 일반 부서가 1대 신청하는 경우(→ false 예상): 장비 데이터(재고 3, 0)를 바꿀 수 없어서 이 사례를 만들 수 없다. 같은 규칙의 경계는 재고 3에 2대 신청(true)과 3대 신청(false)으로 확인했다.
- 대문자 `department=IT`, 빈 값 `department=`의 처리: 확정 정책에 없어 테스트로 고정하지 않았다. 현재 구현을 직접 호출하면 둘 다 422(`literal_error`)가 나온다. 이 동작이 맞는지는 담당자에게 확인해야 한다.
- 브라우저(`/docs`)에서의 확인: 미실행. 아래 결과는 TestClient로 같은 엔드포인트를 호출한 것이다.

## diff 확인: 부서 판단을 처리한 위치, 변경 파일과 이유

- `git status --short` (it_asset_api 기준):
  - `M app/routers/equipment.py`, `M app/services/equipment_service.py`, `?? tests/test_department_availability.py` (+ 이 `logs/02.md`)
  - 상위 폴더 워크시트 변경은 코드와 무관하다.
- `git diff --stat`: `app/routers/equipment.py | 10 +-`, `app/services/equipment_service.py | 6 +-`
- **부서 판단 위치: Service** `app/services/equipment_service.py` `check_availability()`

```diff
-def check_availability(equipment_id: int, quantity: int):
+def check_availability(equipment_id: int, quantity: int, department: str | None = None):
 ...
-    can_allocate = quantity <= available
+    # 일반 부서는 지급 후 최소 1대가 남아야 한다. IT 부서와 부서 생략은 남은 수량까지 가능.
+    reserve = 1 if department == "general" else 0
+    can_allocate = quantity <= available - reserve
```

- **입력 받는 위치: Router** `app/routers/equipment.py` — 선택적 쿼리 매개변수를 추가해 Service로 넘긴다. 허용값 외 입력은 FastAPI가 422로 거절한다.

```diff
+from typing import Literal
 ...
-def check_availability(equipment_id: int, quantity: int = Query(ge=1)):
-    result = equipment_service.check_availability(equipment_id, quantity)
+def check_availability(
+    equipment_id: int,
+    quantity: int = Query(ge=1),
+    department: Literal["it", "general"] | None = None,

```

- 바꾸지 않은 파일: `app/schemas.py`(응답 필드 4개 유지), `app/data.py`(장비 데이터), `app/main.py`, `tests/test_equipment.py`, `checks/`
- 부서를 생략하면 `department=None` → `reserve = 0`이 되어 수정 전 식 `quantity <= available`와 같다. 그래서 기존 요청의 동작이 바뀌지 않는다.
